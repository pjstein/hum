# 0071 · One log serves as both manifest log and release ledger

**Status:** proposed (W0-07, 2026-10-06)

## Context

The manifest spec says every manifest version is logged, and that "the ledger is a log whose entries are release manifests, plus the content store holding their tables." Its open questions ask whether the release ledger and the manifest log are the same log. `services.md` has to pick one to write the log API.

## Decision

Draft 0.1 runs **one reference log**. Releases are entries of type `release` in it. The checks the manifest spec assigns to "the release ledger" (verification step 10 on releases) run on every `release` entry at submission. "The ledger" in product vocabulary means the log filtered to release entries, together with their table blobs.

Fixed alongside:

- Leaf encoding: deterministic CBOR array `[cid, type, authority, lineage or null, version]`, hashed per RFC 6962.
- Checkpoint origin line: `hum/log/<authority CID, text form>`.
- Witness names: `hum/witness/<authority CID, text form>`, or a pre-existing name for a witness that already runs.
- Tiles, checkpoints, cosignatures and the witness protocol are the C2SP formats, served under `/v1/log/`.

## Why

- One log keeps step 9's rule at submission simple: every referenced manifest is already in this log, so the deck and context a release pins are at hand for step 10.
- One set of witnesses to recruit at launch.
- Tessera serves one tree per instance; a second log is a second deployment with the same code, so splitting later is operational, not a format change.
- Readers who want only releases filter by the `type` field in the leaf, which is why the leaf carries it.

## Consequences

- Release entries are interleaved with everything else; a release-only mirror filters.
- If the owner prefers a separate ledger, releases get a second `proofs` entry and a second `service` manifest of kind `log`; `services.md` changes in two sentences.
- `context.md` names accepted logs by authority CID; with one log, every context at launch names the same one.
